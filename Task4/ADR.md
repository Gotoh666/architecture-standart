В будущем передача актуальных ставок в систему кол центра может быть реализовано через кафку для повышения доступности на случай отказа сервиса ставок. На MVP для простоты банковский кол-центр получает ставки напрямую из сервиса ставок. Для быстродействия сервис ставок кеширует ставки (пока в памяти).
Отдельный воркер занимается формированеим файла и передачей в партнерский кол центр для снижения нагрузки на основной сервис и возможности горизонтального масштабирования.
### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Использовать Кафку для передачи файла на sftp сервер. Недостаток: Кафка не предназанчена для передачи файлов.
Не исопльзовать отдельный воркер для формирвоания файла. Недостаток: снижается возможность масштабирования, повышается риск выхода из строя всего сервиса ставок.

**Недостатки, ограничения, риски**
### Недостатки:  
синхронное взаимодействие между сервисом кол-центра и сервисом ставок может стать точкой отказа.  
### Риски:  
сервис ставок как точка отказа, однако решается исопльзованием нескольких инстансов.   
Сбой передачи файла через SFTP, в будущем требуется мониторинг, подверждение отправки, повторные отправки.  
Deposit Service Worker как один cron-job. Если упадёт или не запустится, файл партнёру перестанет отправляться.
### Ограничения:  
Передача ставок в партнерский кол-центр только через файл.  
Внешняя система полностью контролирует обработку файла.
